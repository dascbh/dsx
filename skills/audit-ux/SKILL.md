# Audit UX

> **DSX root:** two levels above this skill's base directory. Paths `knowledge/`, `references/`, `tools/` are relative to it.

References: `knowledge/foundations/ux-dimensions.md` (the 14 dimensions and how to read the report), `data/ux-dimensions.json` (the matrix), `knowledge/foundations/ux-findings.md` (register, ids, status), `knowledge/foundations/ux-md.md` (T/F rules and inputs), skill `ux-writing` (text options), skill `review-ux` (per-screen judgment method).

Difference from `review-ux`: that one reviews a screen or a flow; this one audits a whole module, with a durable register and a per-dimension report, and ends with the decisions applied and a re-audit.

## 1. Prerequisites

The audit is only valid with three project inputs, in this order of importance:

1. **Screen captures from the project's code** (HTML rendered from the real components, never a text-generated screen). Default: `<project>/.dsx/captures/<module>/<nn>-<screen>.html` (configurable in `paths.captures`, see `docs/project-paths.md`; the old `.stitch/<module>/code` folder is still read, with a warning). States (empty, error, loading, no access…) sit next to it: `<nn>-<screen>.<state>.html`. Capturing is the DSX `capture-from-code` skill (or the capture harness the project already has).
2. **Checked flow map**: `<project>/.dsx/maps/flows-<module>.json`, generated by the `map-ux` skill (flow mapper) with file:line evidence and confirmed with the owner through the `confirm-maps` skill. An unchecked map produces false F1/F5.
3. **`UX.md`** at the project root, valid under `node <DSX>/tools/lint-ux-md.mjs UX.md` and **up to date with the product**: the audit runs drift (`tools/ux-lint/ux-md-drift.mjs`) as a prerequisite and warns "UX.md out of date: …" (screen without an archetype, archetype of a screen that is gone, policy most screens do not follow, state without a capture, stale `updated`, expired deviation). Without `UX.md` the DSX defaults apply, and the rules that depend on a declaration (primary action position, required states, forbidden terms, accepted deviations) lose force; with an out-of-date `UX.md`, the findings measure against an old rule. Update it (skill `ux-md`, Mode C) before deciding findings that depend on the flagged point.

Also: the code folders where the text is born (`--code`), so text findings point to file:line; and the **measured geometry** of the captures (`<project>/.dsx/captures/<module>/geometry/*.geometry.json`, generated by `node <DSX>/tools/ux-lint/measure.mjs <captures> --out <folder> --ux UX.md`, which needs Playwright in the project), without which the L layout and hierarchy rules do not run. With `--measure` the audit measures before running.

## 2. Run the audit and record

```bash
node <DSX>/tools/ux-lint/audit.mjs --module <m> --root <project> --register [--measure]
```

The command checks the prerequisites (and says how to generate whatever is missing), runs the detectors that exist (text, screen, flow, layout, states, consistency), writes to `<project>/.dsx/findings/<m>/findings.json` and prints the **per-dimension report**. Paths: flag > `--config <file>`/`.dsx/config.json` > `paths` block of the `UX.md` > default (`docs/project-paths.md`). Defaults: `--screens <root>/.dsx/captures/<m>`, `--geometry <root>/.dsx/captures/<m>/geometry`, `--map <root>/.dsx/maps/flows-<m>.json`, `--ux <root>/UX.md`, `--code` = folders detected from the stack (the `src` of each front-end package); text folders outside the front end (back-end constants, vocabulary) come in through `paths.code`. Without `--register`, it compares against the register without writing (useful before changing anything).

- **IF** a prerequisite is missing **THEN** generate it with the indicated command and run again; do not replace a missing capture with judgment.
- **IF** a detector shows up as missing or outside the register **THEN** its dimension goes to judgment (step 3) this round, and the final report says so.
- **IF** new findings or regressions appear **THEN** start with them.
- **IF** a finding is an intentional product difference (it applies to one rule across several screens) **THEN** declare the deviation in the `deviations` block of the `UX.md` (with `rules` and `screens`) instead of `ignore`-ing them one by one; on the next run it shows up as "accepted deviation", with the reason, and does not count as open. A deviation removed from the `UX.md` reopens the finding.
- The glossary for C3 and X10 is the module's (`content.glossary: { default: …, <m>: … }`); the audit passes `--module` through.

## 3. Judgment of what the machine does not measure

Read each dimension's coverage in the matrix (`data/ux-dimensions.json`), or the "review with" line of the report:

| Coverage (effective) | What to do |
|---|---|
| Automatic rule | Check the findings against the capture (a false positive becomes `ignore` with a reason in step 5) |
| Automatic rule + judgment | Check the findings and review the dimension's **gaps** with its knowledge |
| Judgment | Review screen by screen with the indicated knowledge (the dimension's `knowledge`) |
| Reference only | Use the law or principle to justify and size findings in the other dimensions |

Suggested order: dark patterns (if there is consent, billing or refusal) → information architecture and navigation → heuristics (cognitive walkthrough of the map's journeys, with the four questions from `review-ux`) → states → accessibility (skill `accessibility`) → gaps of the partial dimensions.

Every problem found becomes a case in `cases.json` (format in `knowledge/foundations/ux-findings.md`), with:
- `rule`: the family's rule when it fits (text the detector missed goes in as `X3`, `X4`…); otherwise a review id from `review_rules` in the matrix — `H1`…`H10`, `DP`, `IA`, `A11Y` (WCAG criterion in the message), `LAW` (the law in the message);
- `severity` 0–4 on the scale of `knowledge/foundations/nielsen-heuristics.md`, assigned after gathering them all;
- `problem` with the evidence (screen, region, what is seen) and the violated principle; judgment without a named principle is not a finding;
- `screens` and `source` (file:line when known).

Record with `node <DSX>/tools/ux-lint/findings.mjs options --module <m> --from cases.json --root <project>`: a case that matches a detector finding links the options to it; a new case enters as an `origin: review` finding.

## 4. Propose options

**IF** a flow's findings share the same cause (too many steps, a decision in the wrong place, text explaining what the structure hides) or the archetype no longer fits the task **THEN** do not patch finding by finding: take the flow to the `rethink-ux` skill (3 variations built, measured and compared), with those findings' ids in `resolves`, and keep only the isolated findings here.

For each open finding the owner needs to decide, 2–3 options in `cases.json` itself, with the convention that supports them and one recommended with the reason. Text: follow the `ux-writing` skill (formulas, glossary, verb + object). Layout and actions: cite the archetype and the pattern (`patterns/<category>/<id>.md`). A finding with no real decision (a single, obvious fix) gets a single option.

## 5. Previews and decision page

Generate the previews before the page: for each open case, the "before" and "after" of each option cropped from the real capture (whole dialog or the region around the element, outlined), and the mini flow diagram. Run from a project folder that has Playwright (e.g. the front-end folder, where the `package.json` with `@playwright/test` is):

```bash
cd <project>/<folder-with-playwright>
node <DSX>/tools/ux-lint/audit.mjs --module <m> --root <project> --preview --page <project>/.dsx/findings/<m>/page.html
```

(or `preview.mjs --module <m> --root <project>` and then `findings.mjs page`). The page comes out paginated — `page.html` with the index and `page-2.html`… up to ~10 MB each, images embedded —; choices carry across pages and "Copy decisions" copies those from all of them. To publish as an artifact, the main one goes as the page and the others through `files`. `--preview-files` references the images in `previews/` instead of embedding them (for opening locally, without publishing).

- **IF** an option needs a preview different from the family's default (move instead of changing the text, show another screen as an example, button variant) **THEN** declare `preview` on the option in `cases.json` (operations in `knowledge/foundations/ux-findings.md`, "Option previews").
- **IF** the preview says "element not found" or the crop shows the wrong element **THEN** check the finding's text against the capture (the text may exist only in the empty state or in an attribute) or declare `selector` on the operation.
- **Skip the previews** when the project has no Playwright and installing it is not worth it, when the round only has invisible-text findings (accessible names) or when the owner decides in the chat; the page comes out the same, without the images. Without Playwright, `preview.mjs` still generates the flow diagrams.
- Ignore in the project's git: `.dsx/findings/*/previews/` and `.dsx/findings/*/page*.html` (generated).

The owner picks an option or "Ignore" with a reason and copies the JSON; record it with `findings.mjs import --module <m> decisions.json --root <project>`, or `findings.mjs decide` for a decision stated in the chat. The page is generated, not versioned.

## 6. Apply at the source

Fix where the problem is born: the finding's `source` (file:line), the template and not each variant, the text constant and not the screen. One decision at a time or batched per file. Did a product rule change (action position, required state, forbidden term)? Update the `UX.md` along with it.

## 7. Re-audit

Recapture the changed screens and run step 2 again with `--register`. What disappeared becomes `fixed`; what came back, `regression`. A review finding does not disappear on its own: review the screen and decide again. Hook `findings.mjs check` into the project's pre-commit or CI.

## Product pipeline quality (Forward contract)

The audit also reports the Forward product-pipeline contract (`knowledge/foundations/product-pipeline-ux.md`, matrix `data/pipeline-quality.json`): **UI quality** (5 metrics: information density, semantic economy, action topology, visual hierarchy alignment, interaction friction), **UX quality** (5 dimensions: task effectiveness, cognitive economy, journey topology, expectation/feedback alignment, effort and recovery) and **design-system adherence** as a separate verdict. The 14 dimensions above become the diagnostic layer.

```bash
node <DSX>/tools/ux-lint/criteria.mjs check cycles/C-<n>/plan.md        # declarations: fields, metric ids, dated plan
node <DSX>/tools/ux-lint/audit.mjs --module <m> --root <project> --criteria cycles/C-<n>/plan.md \
     [--evidence <recorded.json>] [--criteria-out <project>/evals/ux/C-<n>-criteria.json]
```

- Criteria come from the `## Acceptance criteria` section of the cycle plan (format in the knowledge file): declared before construction, never written after seeing the result. Inspecting without a plan is valid: every metric reads `unknown — no criterion declared`, and the report says so.
- Each criterion gets value, evidence revision, verdict (`pass | fail | unknown | not-applicable`) and evidence class (`observed | expert-inferred | human | synthetic`). Unknown is never pass; synthetic evidence never decides; a target relative to an unknown baseline stays unknown until the measurement task runs.
- No score: never summarize the audit as one number, and never let a passing DS adherence offset a failed UI/UX metric (or the reverse).
- Judgment findings (step 3) still cite a principle; when they feed a criterion, record them in the evidence file as `expert-inferred`, and in `reviews/<demand-id>/findings.toml` (Forward) with the USE/DOM id.
- The `--json` output and the results file carry `provenance` (date, owner role, sources with revision, criteria, evidence class, assumptions, gaps).

## Final report (default)

```
UX audit · <module> · <date> · commit <sha>
Inputs: <n> screens + <n> state captures · map checked on <date> · UX.md <valid|missing>
Detectors: text ✓ · screen ✓ · flow ✓ · layout <✓|missing> · states <✓|missing> · consistency <✓|missing>

By dimension (effective coverage · open s4/s3/s2/s1 · new · fixed · regressions)
  <dimension> · <coverage> · <a/b/c/d> · <n> · <n> · <n>
  …
Judgment done: <dimensions reviewed by hand> · <n> review findings (rule or heuristic cited)
Decisions: <n> applied · <n> ignored with reason · <n> pending
Re-audit: before <n> open → after <n>; regressions <n>
Still open: <dimension gaps and what needs research with users>
```

Do not declare a dimension "good" just because it has no findings: state its coverage and its gaps.

Add to the final report (after the dimensions):

```
UI quality: density <verdict> · semantics <verdict> · action topology <verdict> · hierarchy <verdict> · friction <verdict>
UX quality: effectiveness <verdict> · cognitive economy <verdict> · journey topology <verdict> · feedback <verdict> · effort/recovery <verdict>
DS adherence (separate): <verdict> — tokens/kit · semantics · rendered parity · interaction/a11y · adoption
Unknown criteria: <ids> and the measurement each one needs
```

## Checklist

- [ ] Captures from the code, checked map and valid `UX.md` before running.
- [ ] `audit.mjs --register` run; register written to `.dsx/findings/<m>/`.
- [ ] Every judgment or reference dimension reviewed with the indicated knowledge; findings with a rule or review id, severity and principle.
- [ ] Flows with same-cause findings sent to `rethink-ux` instead of patched.
- [ ] Options written (text via `ux-writing`), previews generated (or a justified skip) and decision page delivered to the owner.
- [ ] Decisions applied at the source and `UX.md` updated when the product rule changed.
- [ ] Re-audit recorded; final report in the format above.
- [ ] Quality sections read against the cycle plan criteria (or reported as unknown when there is no plan); no single score; DS adherence reported separately.
