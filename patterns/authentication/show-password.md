# Show or hide password: how should it work?

> **Rule:** Hide the password by default and offer an optional button, with an accessible name, that toggles visibility without clearing the value, moving focus or blocking paste and password managers.

## Context

Masking characters reduces visual exposure but increases typing errors, especially on small screens, with long passwords or passwords generated by a manager. That is why sign-in, sign-up and recovery should let people check the value in a clear, optional way.

The control must not interrupt filling in the field: it has to preserve the value, focus, selection and input features such as keyboard, autofill and paste. Exposure should only happen through an intentional action and be easy to undo.

The decision balances error prevention against the risk of exposure in the real context of use.

## Decision

- **IF** there is a password field (sign-in, sign-up, change, reset) **THEN** include a show/hide button.
- **IF** the field opens or after a confirmation **THEN** keep the password hidden.
- **IF** the person activates the button **THEN** toggle visibility, preserving value, selection and focus.
- **IF** the button is in the hidden state **THEN** its accessible name is "Show password"; **IF** visible **THEN** "Hide password".
- **IF** it uses only an icon **THEN** include an accessible name and do not rely only on the icon or color change.
- **IF** the field is a sign-in field **THEN** use `type="password"` with `autocomplete="current-password"`; **IF** it is creation or change **THEN** `autocomplete="new-password"`.
- **IF** the device is mobile **THEN** ensure a comfortable target that does not cover the text or sit right next to another action.
- **ELSE** never reveal the password automatically or block paste.

## When to use

- Sign-in, sign-up, password change and reset.
- Long, generated or hard-to-check passwords.
- Mobile interfaces.

## When to avoid

- Revealing the password automatically → **use instead:** an explicit action.
- An ambiguous icon with no accessible text → **use instead:** a named button.
- A context where exposure is unacceptable by policy → **use instead:** keep it hidden and strengthen typing support (paste, password manager).

## Do

- Use a real button next to the field.
- Preserve value, focus and selection when toggling.
- Allow typing, pasting and password managers.
- Keep contrast and visible focus.
- Test creation, sign-in, change and recovery.

## Avoid

- Clearing, truncating or reformatting the password when toggling.
- Moving focus or closing the on-screen keyboard unnecessarily.
- A small target.
- An unidentified state.
- Blocking autofill or paste.

## Accessibility

- The button is a real `<button>`, activated by Enter and Space (2.1.1).
- The accessible name reflects the current action and the state is conveyed (4.1.2).
- Hide the decorative icon from the screen reader when the name already announces the action.
- Allowing paste and password managers supports accessible authentication (3.3.8), and correct autocomplete meets 1.3.5.
- A sufficient touch area (2.5.8) and visible focus (2.4.7).

## Verification checklist

- [ ] The password starts hidden.
- [ ] The button has an accessible name that states the next action.
- [ ] The value stays intact when toggling.
- [ ] Focus remains predictable.
- [ ] The control works with the keyboard.
- [ ] The target is comfortable on mobile.
- [ ] Paste and autofill work.
- [ ] Password managers work.
- [ ] Exposure depends on an explicit action.
- [ ] It was tested with a screen reader.

## Rationale

- NIST SP 800-63B (password verifiers and user experience considerations): an option to display the password, allowing managers and paste.
- WCAG 2.2, 3.3.8 (accessible authentication): optional show password, autofill and paste.
- W3C WAI-ARIA APG (Disclosure) and technique H100: operable button, accessible names and autocomplete.
- GOV.UK Design System (Password input) and USWDS (sign-in page): field hidden by default and a text control.
- Material Design: toggling between masked and visible in the password field.
- Brazilian Government Digital Standard GOV.BR (Input): structure and states of fields.
